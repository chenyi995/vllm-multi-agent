# T8 · Role-play / Simulation（角色扮演）

> 术语见 [`README.md`](README.md)，本文不重复定义｜代码：`kvpim/workloads/t8_roleplay.py`

## 一句话

**两个 agent 扮演一对角色协作完成任务：一个只负责下指令，另一个只负责给方案，
轮流说话直到任务完成或撞上 40 条消息的上限。**

---

## 1. 模拟的是什么

来自 **CAMEL**（Li et al., NeurIPS'23）的 **Inception Prompting**。
它的设计目标是让两个模型实例**不跑题、不互换角色**，全靠两段很长的规则说明约束：

```
AI User      "===== RULES OF USER ====="       只能用两种方式下指令，说完任务就回 <CAMEL_TASK_DONE>
AI Assistant "===== RULES OF ASSISTANT ====="  必须以 "Solution:" 开头，以 "Next request." 结尾
```

**两段提示词逐字节取自 `ref/camel/camel/prompts/ai_society.py`**
（`ASSISTANT_PROMPT` 996 字符 / `USER_PROMPT` 1,444 字符），
`analyze.check_camel_reference` 每组配置自动校验，篡改一个词立即失败。

## 2. 为什么这个拓扑在矩阵里

**它是"两个 agent 看同一份历史、但各自挂不同长度的系统提示词"的纯粹形态**：

```
ai_user 的输入      = [USER_PROMPT 1,444 字符][整段对话，角色视角为"我问你答"]
ai_assistant 的输入 = [ASSISTANT_PROMPT 996 字符][同一段对话，角色视角互换]
                       ^^^^^^^^^^^^^^^^^^^^ 差 448 字符
```

**同一句话在两边落在完全不同的位置。** 这正是 Q1 要量的东西。

## 3. 具体任务

**CAMEL AI Society** —— 50 × 50 个角色对 × 10 个任务 = 25,000 段对话的数据集。
按 assistant 角色分层抽 10 个 `(assistant_role, user_role, specified_task)` 三元组：

```
Translator          <-> Yoga instructor       翻译 10 张瑜伽哲学海报和 20 幅曼陀罗…
Actor               <-> Accountant            协助会计追踪成本…
Personal Assistant  <-> Social media manager  提出至少三个创意方案…
Editor              <-> Social media manager  制定个性化回复计划…
Researcher          <-> Photographer          帮摄影师找改进方法…
```

**终止条件**：`<CAMEL_TASK_DONE>`，或硬上限 **40 条消息**。
计划 §3 特意点了这个上限——它是 T8 工作集可控的原因
（原本担心 T8 撑爆显存，看到 40 条上限后解除）。

## 4. 一段对话怎么跑

**真实 trace（`T8_w00`）**：

```
call  角色            输入    输出   缓存命中
 0    ai_user          352      35       0
 1    ai_assistant     291     118       0
 2    ai_user          513      40     384     ← 接上自己上一轮
 3    ai_assistant     457     282     400
 4    ai_user          843      43     544
 5    ai_assistant     790     284     736
 6    ai_user         1178      43     880
 7    ai_assistant    1125     336    1072
```

**两个特征**：

**① 双方各自的输入都单调增长，且各自内部命中很高**（384 → 544 → 880；
400 → 736 → 1072）。因为每一方的输入都是"自己固定的 SYS + 只增不改的对话"，
前缀能一直命中。**T8 的前缀命中率 91.8%，是九类最高。**

**② 但两边互相之间一个块都共享不了。** `ai_user` 的输入长 352 而
`ai_assistant` 的只有 291——同样的对话内容，因为前面挂的规则说明长度差 448 字符，
**整体平移**。

**每段对话的调用数分布**：

```
[7, 9, 9, 9, 11, 17, 19, 40, 40, 40]      共 201 次
                            ↑ 三段打满 40 条上限
 ↑ 七段提前收到 <CAMEL_TASK_DONE>
```

## 5. 量出来了什么

`block 档 16、充足档`：

```
调用 201 次   W_mean = 16,644 token   W_max = 43,424   耗时 32.3 分钟
N_total = 10,403 个 block
候选（有内容孪生）= 1,241 个，占 11.9%
前缀命中率 91.8%     ← 九类最高
```

| 视角 | L0 | L8 | L17 | L26 | L35 | 5 层全判同 |
|---|---|---|---|---|---|---|
| `K_post` | 200 | 128 | 193 | 200 | 188 | 128 |
| `K_derope` | **1,241** | 128 | 281 | **630** | 498 | 128 |
| `V` | **1,241** | **12** | 195 | 323 | 154 | 12 |

**de-RoPE 在第 0 层增益 6.2×（200 → 1,241），九类里第二大**，仅次于 T1 的 14.2×。
原因就是 §2 说的规则说明长度差造成的整体平移。

**T8 还有一个九类里独有的性质：深层保留最多。** `K_derope` 在 **L26 有 630**，
是所有拓扑里深层数字最高的（T1 的 L26 只有 526、且候选基数大得多）。
双 agent 对话的历史结构最规整——同一段话在两边的**上下文其实是同一段对话**，
只是角色标签和前缀长度不同，所以深层的差异比其它拓扑小。

**`V` 在第 8 层塌到 12**（其余层上千）。V 不过 RoPE，按理不该这样。
这个异常在 T3（466）、T4（0）也出现，**暂无解释**。

## 7. 适用边界

1. **无工具环境**：两个 agent 只能对话，`specified_task` 里要求的翻译、
   建表、拍照都做不了，产出全是文字方案。对 KV 统计口径无影响。
2. **抽题按 assistant 角色分层**，不是原文的完整 50×50 网格。
3. **受限档的 KVFlow 比例是 2.000**（池子 33,280 vs W_mean 16,644）——
   容量下限被 22,177 token 的最长单次调用顶穿，"受限"名不副实，
   虽然仍然发生了 2,625 块的驱逐。做 Q3 时要注意。
4. τ 是工作值；`max_tokens=1024` 的混淆见 [`README.md`](README.md)。
