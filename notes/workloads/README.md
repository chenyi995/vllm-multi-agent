# 公共背景

## 1. token

模型不直接处理字符，而是处理 **token** —— 文本被切成的小单位，大致相当于一个词
或半个词。比如 `triples_sum_to_zero` 会被切成好几个 token。

本文所有长度都以 token 计。

## 2. 层（layer）

大模型不是一个整体，而是**同样结构的模块堆叠**而成。本实验用的 Qwen3-4B 堆了 **36 层**。

一个 token 进入模型后，**依次穿过全部 36 层**，每一层都会为它产出一份中间结果。

> **关键**：一个 token 在缓存里不是存一份数据，而是**每层各存一份，共 36 份**。

层与层的区别，是理解本实验结论的关键：

```
第 0 层的输入  = 这个 token 自己（词嵌入 + 位置）
                → 第 0 层的产物只取决于"这是哪个词、在第几位"

第 1 层的输入  = 第 0 层的输出。而第 0 层的注意力机制已经把前面所有 token
                的信息混了进来
                → 第 1 层的产物已经取决于"前面说过什么"

……逐层累积，到第 35 层，产物里混的几乎是整段上下文
```

**浅层认字，深层认上下文。**

## 3. K 和 V，以及 KV cache

模型生成文字是**一次一个 token**。生成第 N 个时要"回看"前面 N−1 个，每次重算是 O(N²)。

所以每个 token 第一次被处理时，模型为它算出两个向量并存下来：

- **K**（key）—— 用来被后面的 token"检索"
- **V**（value）—— 被检索到时提供的内容

**每层各一份 K 和一份 V。** 存这些东西的显存池就叫 **KV cache**。

对硬件视角：**这是一块 write-once 的内存池**，条目写入后不再修改，只会被整块淘汰。

Qwen3-4B 的具体尺寸：

```
36 层 × 8 个 KV head × 128 维 × 2 份(K和V) × 2 字节(bf16)
  = 147,456 字节 = 144 KiB  ← 每个 token 占的显存
```

一段 10 万 token 的上下文就是 **14 GB**。这是推理系统的主要显存开销，也是值得去重的原因。

（**head**：注意力被拆成若干条并行的"通道"，本模型的 K/V 有 8 条，每条 128 维。
对本实验来说它只影响向量尺寸，不影响结论。）

## 4. block（块）

vLLM（我们用的推理引擎）不按 token 分配显存，而是**按固定大小的块**分配，
和操作系统分页一样：

```
1 个 block = 16 个 token 的 KV      （16 是默认值；本实验还扫了 4 / 8 / 32 / 64）
1 个 block = 16 × 144 KB = 2.25 MB   （全部 36 层加起来）
```

> **block 是缓存复用的最小单位。** 本实验数的"重复"，数的就是 block。

## 5. 前缀共享，以及重复是怎么产生的

如果两个请求**从第 0 个 token 开始、连续完全相同**，vLLM 会让它们**指向同一个物理
block**（和写时复制的页共享一个道理）。这叫**前缀共享**。

硬性前提是"从头开始连续相同"，中间对上一段**不算**。

而 multi-agent 系统天天在做的事，恰恰是"同样的内容出现在不同位置"：

```
Agent A 的输入:  [系统提示词 A][任务描述]
Agent B 的输入:  [系统提示词 B][任务描述]
                  ^^^^^^^^^^^^ 这里就不同了
                              ^^^^^^^^ 这段完全相同，但共享不了
```

于是同一段文字的 KV 被**算了两遍、存了两份**。这就是我们要数的**重复 block**。

（**系统提示词**：放在对话最前面、用来设定 agent 身份和行为的一段固定文字。
"agent" 在本实验里不是进程也不是模型副本，**就是一段系统提示词**。）

## 6. RoPE：为什么"内容相同"≠"数据相同"

模型必须知道每个 token 在句子里的**位置**。Qwen3 用的方法叫 **RoPE**（旋转位置编码）：

把 K 向量的 128 维**两两配对**成 64 个二维向量，每一对按该 token 的位置**旋转一个角度**：

```
位置 0   的 token → 旋转 0°
位置 64  的 token → 旋转某个角度
位置 608 的 token → 旋转另一个角度      （角度随位置变化）
```

**后果**：同一段文字，出现在位置 64 和位置 608，算出来的 K **数值完全不同**。
**内容一样，比特不一样。**

- 光看内容 → 理论上可以去重
- 看缓存里实际存的比特 → 实际去不了

**de-RoPE** 就是离线把这个旋转**反过来转回去**，还原成"不带位置"的 K。
这是纯数学逆运算，不需要重新跑模型。

**V 不经过 RoPE**，所以 V 是个天然对照组——它本来就不受位置影响。

## 7. 三个视角

| 视角 | 含义 | 回答什么 |
|---|---|---|
| `K_post` | 缓存里**实际存**的 K（带位置旋转） | 现状能去重多少 |
| `K_derope` | 离线把旋转反转回去的 K | 位置无关存储能去重多少 |
| `V` | 本来就不带位置 | 天然对照 |

**`K_derope` 与 `K_post` 的差 = 位置编码吃掉的可去重量。** 这是本实验的核心问题。

## 8. 我们数的是什么：一个漏斗

```
n_total              这次运行，缓存里存过的物理 block 总数
   ↓ 只有 token 内容完全一样的块，才可能去重（内容不同的根本不是候选）
n_blocks_in_groups   有"内容孪生兄弟"的块数              ← 理论天花板
   ↓ 内容相同不代表数值相同，还要逐块比对数值
n_dup                数值上真的判定为相同的块数          ← 实际可去重量
```

## 9. 怎么判"数值相同"：τ

比对用 **cosine 相似度**（两个向量夹角的余弦：完全同向 = 1，无关 = 0）。
阈值叫 **τ**。

τ 不是拍脑袋定的。我们先做一个对照实验：让同一批内容在机器上**重算一遍**，量出
**浮点运算本身的噪声**有多大，把 τ 定在那个噪声的边界（P1 分位）上。

> **"相同"的定义 = 差别不超过这台机器重算同一件事时自己会产生的差别。**

因为噪声**逐层累积**（第 N 层的输入是第 N−1 层带误差的输出），τ 是**逐层**标定的：

| 层 | 0 | 8 | 17 | 26 | 35 |
|---|---|---|---|---|---|
| τ | 0.99999 | 0.99998 | 0.97809 | 0.96400 | 0.99648 |

⚠️ 当前是**工作值**，取自单条 prompt 的标定，正式跑批后要用真实数据重标。

## 10. 采样层：运行时存 36 层，落盘只取 5 层

**真实 serving 必须存全部 36 层，一层都不能少**——生成每个新 token 时，它要在每一层
都和前面所有 token 做注意力，跳过任何一层那一层就算不出来。

**本实验运行时也是 36 层**。引擎我们一行没改，缓存里存的和真实 serving 完全一样。
我们只是在每次调用结束后，把其中 **5 层：0 / 8 / 17 / 26 / 35**（浅、中、深）的张量
**额外拷一份到硬盘**供离线比对。dump 是一条只读旁路。

存全 36 层要多 7.2 倍硬盘：

```
 5 层 : 2 × 5  × 8 × 128 × 2 字节 =  20 KiB / token   →  全实验约 444 GB
36 层 : 2 × 36 × 8 × 128 × 2 字节 = 144 KiB / token   →  全实验约 3.2 TB
```

### 采样对结果有什么影响

**不受影响**：引擎行为、缓存占用、淘汰、命中率、工作集 W、block 事件流——这些全部
是 36 层的真实情况，因为引擎本来就在存 36 层。

**受影响**：只有"这两个 block 算不算相同"这一判断的分辨率。逐层的数字对**那一层**
是精确的，但——

> ⚠️ 真要在硬件上去重两个 block，它们**36 层全都得相同**（一个物理 block 装的是
> 全部 36 层）。我们只检查了 5 层，可能放过某个在第 12 层其实不同的块对。
> **所以"5 层全判同"是真实"36 层全判同"的一个上界**，真实值只会更小。
> 小多少目前未测——需要挑一组把 36 层全 dump 出来做对照才能标定。

结果表里的"全层判同"指的是**这 5 个采样层全都判同**（最严口径，且是上界）；
"任一层"指至少一层判同（最松口径）。

层深本身就是核心自变量（上下文污染逐层累积），所以采样层的**选取**是设计；
但采样的**数量**是硬盘约束下的取舍，代价如上。

## 11. 一次运行的组织：workflow / call / agent

```
一组配置 = 一个拓扑 × 一个 block 档 × 一个容量档
  └─ 10 个 workflow（= 10 道题，每道题独立跑一遍完整的 multi-agent 流程）
       └─ 若干次 call（= 一次 LLM 调用，一个 agent 说一次话）
```

每个 workflow 开始前会**清空缓存**，所以 workflow 之间不共享。

## 12. 两个容量档

| 档 | 显存池 | 用途 |
|---|---|---|
| **充足档（ample）** | 大到单个 workflow 内不会发生淘汰 | 测"总共有多少重复"（本文结果都来自这里）|
| **受限档（limited）** | 压到工作集的一半 | 测"被淘汰掉的块里有多少本来是重复的" |

（**淘汰 / 驱逐**：显存池满了，vLLM 按最近最少使用把旧 block 踢掉。踢掉不影响正确性，
只是下次要重算。）
