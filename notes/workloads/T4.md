# T4 · Debate（辩论）

> 术语见 [`README.md`](README.md)，本文不重复定义｜代码：`kvpim/workloads/t4_debate.py`

## 一句话

**三个 agent 各自独立解题，然后每人看到另外两人的答案，再答一遍。**

---

## 1. 模拟的是什么

来自 **Du et al.（ICML'24）**。原文参数：**3 个 agent × 2 轮**，`random.seed(0)` 抽 100 题。
我们照搬 3 × 2，抽 10 题。

**提示词逐字节取自 `ref/llm_multiagent_debate/gsm/gen_gsm.py`**：

```python
# 初始提问
"Can you solve the following math problem? {} Explain your reasoning. Your final
 answer should be a single numerical number, in the form \boxed{answer}, at the
 end of your response. "

# 第二轮的辩论消息（construct_message）
"These are the solutions to the problem from other agents: "
  + "\n\n One agent solution: ```{}```" × 每个其他 agent
  + "\n\n Using the solutions from other agents as additional information, can you
     provide your answer to the math problem? \n The original math problem is {}. ..."
```

## 2. 为什么这个拓扑对本实验特别重要

计划 §3 直接把 T4 标为 **"位置错配主战场"**：

> *"每个 agent 看到的他人发言顺序不同"*

agent_1 看到的是 `[agent_0, agent_2]` 的答案，agent_2 看到的是 `[agent_0, agent_1]` 的。
**同样一段 agent_0 的答案，在两个人的输入里落在同一位置；但 agent_1 和 agent_2 的答案
互换了位置**。这是"同内容异位"的教科书式来源。

## 3. 具体任务

**GSM8K** —— 小学数学应用题。按原文的做法 `random.seed(0)` 打乱后取前 10。

## 4. 一道题怎么跑

**真实 trace（`T4_w00`）**，6 次调用 = 3 agent × 2 轮：

```
call  角色       输入   输出   缓存命中
 0    agent_0     88    202       0     ← 轮 0：三人拿到完全一样的问题
 1    agent_1     88    202      80     ← 命中！和 agent_0 的输入一字不差
 2    agent_2     88    202      80
 3    agent_0    820    185     288     ← 轮 1：接在自己轮 0 的对话后面
 4    agent_1    820    185     816
 5    agent_2    820    185     816     ← 几乎全命中
```

**三个可以直接读出来的现象**：

**① 轮 0 三个 agent 的输入完全相同** → agent_1/2 各命中 80 token（88 减去引擎
必留的最后一块）。这是九类里前缀共享最干净的一次。

**② 轮 1 的输入是"自己轮 0 的对话 + 辩论消息"**。我的编排里每个 agent 维护自己的
累积对话（照搬原文的 `agent_contexts`），所以 agent_0 命中 288 = 问题 + 自己轮 0 的回答。

**③ agent_1/2 在轮 1 命中 816**，而输入是 820 token。816 = 51 × 16，**正好是按块
对齐后的全部前缀**——不是"共享了一长段"，是**一个 token 都没分叉**。
原因见下面 §5.1：`temperature=0` 让 agent_1 和 agent_2 的整段对话逐字节相同。

原因不是辩论的结构，是 §5.1 说的退化：**三个 agent 里有两个的对话逐字节相同**，
同内容块当然也同位置，post-RoPE 就已经相等。

### 5.1 三个"辩论者"没有在辩论

Tier 2 的记录项 `replies_identical` 在 **10/10 个 workflow 全中**。展开看：

```
第 0 轮三个 agent 的输入逐字节相同（§4 ①），temperature=0 → 输出也相同
        ↓
第 1 轮 agent_1 与 agent_2 的完整对话逐字节相同   10/10 个 workflow
        其中三人全同                              4/10 个 workflow
```

**为什么是"1 和 2 相同、0 不同"而不是三人全同？** 看第 0 轮的缓存命中：

```
workflow  第0轮三人回答     三人的缓存命中
T4_w00    012 全同         [0, 80, 80]
T4_w01    12 同, 0 异      [0, 80, 80]
T4_w03    12 同, 0 异      [0, 96, 96]
T4_w06    012 全同         [0, 112, 112]
```

agent_0 命中 `0`，走**完整 prefill**；agent_1/2 前缀全命中，**只算最后一个 token**。
prefill 形状不同 → 数值噪声 → 贪心解码路径分叉。所以 agent_1 与 agent_2 永远一致，
agent_0 单独一个样，10 个 workflow 无一例外。

**这条要单独记住：T4 仅有的那点"多样性"，来源是我们正在测量的缓存机制本身。**
工作负载的内容反过来依赖被测对象。

原文靠采样温度（gpt-3.5 默认）拿到三份不同的初始答案；本实验把温度锁成 0
（计划的全局规则，为可复现），辩论就退化成复述。**已决定保持 `temperature=0`**，
代价记在 §7。

**de-RoPE 只多找出 69 个块**（529 → 598）——**T4 的 de-RoPE 增益反而是九类里较小的**。

> **这一点值得注意，因为它与计划的先验预期相反。** 计划 §5.3 把 T4 列为
> "主要损失是位置错配"。实测下来，大部分同内容块本来就同位置，
> 位置错配的量没有预期的大——但**成因不是辩论结构对齐，是 §5.1 的退化**：
> agent_1 与 agent_2 的对话逐字节相同，它们之间根本不存在"顺序不同"的错位。
> 真正错位的只有 agent_0 与另外两人之间那一段。
>
> 如果把轮数加到 3 轮以上（计划 §3 提到"要拉长 trace 可扩到 3 轮"），
> 位置错配的量应该会显著上升。**这是一个值得单独做的对照。**

`V` 在第 8 层是 **0**——和 T3 的 466、T5/T6 的塌陷同一现象，暂无解释。

## 7. 适用边界

1. **`temperature=0` 让辩论退化**（§5.1）：三个 agent 里必有两个的对话逐字节相同。
   影响两处——
   **(a) T4 的数字是"位置错配"的乐观上界**：peer 块常常是同一段文本落在不同偏移上，
   这把同内容异位的量推到最大；
   **(b) §2 引的"每个 agent 看到的他人发言顺序不同"在本实现里只对 agent_0 成立**，
   agent_1 与 agent_2 之间无差别。
   **已拍板保持 `temperature=0`**（全实验一致、可复现优先）。
   要恢复原文行为需给第 0 轮开采样并固定种子，T4 的 10 组全部重跑。
2. **只跑了 2 轮**（原文默认）。位置错配的量与轮数强相关，2 轮可能低估。
3. **Tier 1 校验的题面部分是弱判据**：原文把题面提示词内联在 `__main__` 里，
   没有常量可取，所以只能判"我们这份出现在该文件的字符串字面量集合中"。
   辩论轮的提示词是拿原文 `construct_message` 跑合成输入比的，这部分是强判据。
4. **没有 MMLU**：计划 §3 写的是"GSM8K + MMLU 子集"，目前只做了 GSM8K。
5. τ 是工作值；`max_tokens=1024` 的混淆见 [`README.md`](README.md)。
