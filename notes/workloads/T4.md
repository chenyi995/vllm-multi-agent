# T4 · Debate（辩论）

> 术语见 [`README.md`](README.md)，本文不重复定义｜代码：`kvpim/workloads/t4_debate.py`

## 一句话

**三个 agent 各自独立解题，然后每人看到另外两人的答案，再答一遍。**

---

## 1. 模拟的是什么

来自 **Du et al.（ICML'24）**。原文参数：**3 个 agent × 2 轮**，`random.seed(0)` 抽 100 题。
我们照搬 3 × 2，抽 10 题。

**提示词逐字节取自 `ref/llm_multiagent_debate/gsm/gen_gsm.py`**：

```python
# 初始提问
"Can you solve the following math problem? {} Explain your reasoning. Your final
 answer should be a single numerical number, in the form \boxed{answer}, at the
 end of your response. "

# 第二轮的辩论消息（construct_message）
"These are the solutions to the problem from other agents: "
  + "\n\n One agent solution: ```{}```" × 每个其他 agent
  + "\n\n Using the solutions from other agents as additional information, can you
     provide your answer to the math problem? \n The original math problem is {}. ..."
```

## 2. 为什么这个拓扑对本实验特别重要

计划 §3 直接把 T4 标为 **"位置错配主战场"**：

> *"每个 agent 看到的他人发言顺序不同"*

agent_1 看到的是 `[agent_0, agent_2]` 的答案，agent_2 看到的是 `[agent_0, agent_1]` 的。
**同样一段 agent_0 的答案，在两个人的输入里落在同一位置；但 agent_1 和 agent_2 的答案
互换了位置**。这是"同内容异位"的教科书式来源。

## 3. 具体任务

**GSM8K** —— 小学数学应用题。按原文的做法 `random.seed(0)` 打乱后取前 10。

## 4. 一道题怎么跑

**真实 trace（`T4_w00`）**，6 次调用 = 3 agent × 2 轮：

```
call  角色       输入   输出   缓存命中
 0    agent_0     88    202       0     ← 轮 0：三人拿到完全一样的问题
 1    agent_1     88    202      80     ← 命中！和 agent_0 的输入一字不差
 2    agent_2     88    202      80
 3    agent_0    820    185     288     ← 轮 1：接在自己轮 0 的对话后面
 4    agent_1    820    185     816
 5    agent_2    820    185     816     ← 几乎全命中
```

**三个可以直接读出来的现象**：

**① 轮 0 三个 agent 的输入完全相同** → agent_1/2 各命中 80 token（88 减去引擎
必留的最后一块）。这是九类里前缀共享最干净的一次。

**② 轮 1 的输入是"自己轮 0 的对话 + 辩论消息"**。我的编排里每个 agent 维护自己的
累积对话（照搬原文的 `agent_contexts`），所以 agent_0 命中 288 = 问题 + 自己轮 0 的回答。

**③ agent_1/2 在轮 1 命中 816（输入 820 的绝大部分）**：因为它们的辩论消息里
`agent_0 的答案` 排在第一个，两人共享 `[问题 + 自己的答案 + "These are the solutions..."
+ agent_0 的答案]` 这一长段。**分叉点在第二份他人答案处**——正是位置错配发生的地方。

## 5. 量出来了什么

`block 档 16、充足档`：

```
调用 60 次   W_mean = 2,155 token   W_max = 7,104   耗时 6.5 分钟
N_total = 1,347 个 block
候选（有内容孪生）= 598 个，占 44.4%
```

| 视角 | L0 | L8 | L17 | L26 | L35 | 5 层全判同 |
|---|---|---|---|---|---|---|
| `K_post` | 529 | 108 | 462 | 490 | 414 | 102 |
| `K_derope` | **598** | 108 | 476 | 515 | 425 | 102 |
| `V` | **598** | **0** | 344 | 358 | 154 | 0 |

**T4 的 `K_post` 在第 0 层已经有 529/598 判同**——比例是九类里最高的之一。
原因就是上面 ①②③：辩论的结构让**很多同内容块恰好也落在同一位置**
（三个 agent 的对话是对齐的），这些块 RoPE 转出来的角度相同，post-RoPE 就已经相等。

**de-RoPE 只多找出 69 个块**（529 → 598）——**T4 的 de-RoPE 增益反而是九类里较小的**。

> **这一点值得注意，因为它与计划的先验预期相反。** 计划 §5.3 把 T4 列为
> "主要损失是位置错配"。实测下来，在**我们这个 3 agent × 2 轮、对话严格对齐**的实现里，
> 大部分同内容块本来就同位置，位置错配的量没有预期的大。
> 真正错位的是"第二份他人答案"那一段，占比不高。
>
> 如果把轮数加到 3 轮以上（计划 §3 提到"要拉长 trace 可扩到 3 轮"），
> 位置错配的量应该会显著上升。**这是一个值得单独做的对照。**

`V` 在第 8 层是 **0**——和 T3 的 466、T5/T6 的塌陷同一现象，暂无解释。
