# T7 · Reflection / Generator-Critic（自我反思）

> 术语见 [`README.md`](README.md)，本文不重复定义｜代码：`kvpim/workloads/t7_reflection.py`

## 一句话

**写一版代码 → 写测试并真的跑一遍 → 失败就反思为什么错 → 带着反思重写。**

---

## 1. 模拟的是什么

来自 **Reflexion**（Shinn et al., NeurIPS'23）。三个组件循环：

```
Actor            写实现
Evaluator        写单元测试，并真的执行
Self-Reflection  失败时分析"为什么错、下次怎么改"
```

**记忆只留最近一条反思**（原文的 Ω = 1），迭代上限 `max_iters=2`（官方 repo 默认）。

Actor 与 Evaluator 在缓存里是**兄弟分支**：都接着同一段历史，但挂不同的系统提示词。

⚠️ **T7 的三个组件提示词是我写的**——Reflexion 的 repo 里提示词与它的框架耦合，
没有可以逐字节对齐的独立常量。这是九类里两个没有 Tier 1 校验的拓扑之一（另一个是 T2）。

## 2. 判定来自真执行，不是模型自评

Evaluator 只负责**写 assert 测试**，判定来自**真的起一个子进程跑解释器**：

```
独立子进程 + 临时目录 + 10 秒墙钟上限 + 2 GB 内存上限 + 最小环境变量
```

实测能正确拦下死循环（10 秒被杀）和内存炸弹（MemoryError）。
失败时真实的 `Traceback` 被喂进 Self-Reflection，所以反思读到的是
`AssertionError: ...` 这种具体错误，不是模型的主观印象。

⚠️ **这是资源沙箱不是安全沙箱**：生成的代码仍能读写文件、起子进程、联网。
HumanEval 是标准 benchmark、生成的是字符串/数学题解法，实际风险低，
但这条边界应当知道。集群无 root，装不了 bubblewrap 一类的真隔离。

一次就做对的题不会产生迭代 trace，Reflexion 评测的就是失败集。

## 4. 一道题怎么跑

**真实 trace（`T7_w02`，一道需要反思的题）**：

```
call  组件               输入   输出   缓存命中
 0    actor               146    219      0     ← 只有函数签名
 1    evaluator           393    165      0     ← 签名 + 实现
      ↓ 真跑测试 → 失败
 2    self_reflection     444    251      0     ← 签名 + 实现 + traceback
 3    actor               624    322    128     ← 签名 + 上版实现 + 反思
 4    evaluator           495    185    288
```

**每题的调用数分布**：

```
[2, 2, 5, 5, 5, 5, 5, 5, 5, 5]      共 44 次
 ↑ 两道题第一轮就通过（actor + evaluator 就结束）
      ↑ 八道题失败，走完 actor→eval→reflect→actor→eval
```

**注意 call 3 和 4 命中了 128 / 288**：第二轮的 actor 提示词以同样的
`"Implement this function." + 签名` 开头，evaluator 也一样，所以前缀能接上。
**这是九类里少数几个"同一 agent 跨迭代命中"的例子。**

## 5. 量出来了什么

`block 档 16、充足档`：

```
调用 44 次   W_mean = 3,923 token   W_max = 7,184   耗时 5.5 分钟
N_total = 2,452 个 block
候选（有内容孪生）= 873 个，占 35.6%
前缀命中率 15.9%
```

| 视角 | L0 | L8 | L17 | L26 | L35 | 5 层全判同 |
|---|---|---|---|---|---|---|
| `K_post` | 640 | 90 | 340 | 396 | 150 | 88 |
| `K_derope` | **873** | 90 | 426 | 494 | 174 | 88 |
| `V` | **873** | 70 | 198 | 252 | 80 | 70 |

**de-RoPE 在第 0 层增益 1.4×（640 → 873），是九类里偏小的。**

原因：三个组件的提示词都以**同一段函数签名**开头，而且签名在每次调用里都排在
差不多的位置（前面只有各自的组件说明，长度接近）。所以大量同内容块**本来就同位置**，
post-RoPE 下已经能配上 640 个。

真正错位的是"上版实现"和"反思"这两段——它们在 actor 的第二轮提示词里出现，
而在 evaluator 的提示词里位置不同。

## 7. 适用边界

1. **三个组件的提示词是自拟的**，无 Tier 1 校验。Tier 2 覆盖两条：
   阶段循环合法（actor→evaluator→reflection→actor）、Ω=1 记忆上限。
2. **Evaluator 自己写的测试比官方测试宽松。** 十道题都是 baseline 用**官方测试**
   判失败的，但在 T7 里用**自写测试**判定时有两道一轮就"通过"了。
   这是 Reflexion 原文机制的固有性质（内层用自写测试、外层才用官方测试），
   照搬了，但它意味着**迭代次数被低估**。
3. **`max_iters=2`**（官方默认）。计划 §3 提到"要拉长 trace 可调大"，没做。
4. **沙箱是资源沙箱不是安全沙箱**（见 §2）。
5. τ 是工作值；`max_tokens=1024` 的混淆见 [`README.md`](README.md)。
